## Common validity and candidates

For an exactly-one-source date, common validity `V` requires all of:

- observed/unmasked `QC_Night`;
- observed/unmasked `LST_Night_1km` raw value in the provider range `7500–65535`;
- observed/unmasked `Night_view_time` raw value in `0–240`;
- observed/unmasked `Night_view_angle` raw value in `0–130`.

Let unsigned QC byte `q` decode as `M=q&3`, `D=(q>>2)&3`, `E=(q>>4)&3`, and `T=(q>>6)&3`.

- A = `V & M=0`. D/E/T remain reported and do not gate A.
- B = `V & M∈{0,1} & D=0 & E=0 & T=0`. B is split into M0 and M1 tiers.
- C = `V & M∈{0,1} & D=0 & E≤1 & T≤1`. C preserves the strict B subset and splits the moderate `C\B` additions into M0 and M1.
- D codes 2 and 3 are excluded from B/C; D1 is diagnostic only and is not admitted by B/C.

No candidate is selected or adopted.

## Exact comparison evidence

Every treatment-date record must contain coordinate-free evidence for:

- fixed 256-element QC-byte pixel-count and pixel-area histograms conditional on V; array index is exact raw byte `0–255`, so the declared bit formulas form the decoded M/D/E/T joint table without lossy aggregation;
- A, B, C, B-M0, B-M1, C-minus-B-M0, C-minus-B-M1, M0-D>0, M1-D0/1/2/3, and D1 diagnostic counts, areas, and eligible-area fractions;
- a fixed QC/LST mask-and-provider-range cross-tab, distinguishing masked, observed-out-of-range, and observed-in-range LST within masked/observed QC states;
- daily coverage and explicit zero/missing-date counts, and seasonal summaries without combining streams;
- the four disjoint comparison groups `A∩B`, A-only, B-only, and `C\B`, plus aggregate B for the approved B-versus-`C\B` comparison, with count, area, mean, min, max, and Type-7 5/25/50/75/95 percentiles for LST °C, local-solar view time, view angle, and scaled-but-uninterpreted `Clear_night_cov`; a group with zero pixels reports its real (zero) count and area with explicit null `mean`/`min`/`max`/percentiles, and is never interpolated or dropped;
- coordinate-free mean-temperature contrasts for `A∩B` versus A-only and aggregate B versus `C\B` only when both sides contain values;
- daily and seasonal shoreline sensitivity relative to the original 0 m treatment.

Client admission must prove the exact 256-byte truth table, B⊆C, exact B and C tier partitions, exact histogram-to-metric identities, fraction identities, finite/nonnegative values, cross-tab partitions, distribution schemas, exactly one source image, source/projection identity, and all fixed key grids before accepting a result.

## Deterministic original NASA HDF verification

For each stream-season with any M0,D>0 pixel in the original 0 m treatment, select the earliest date (via the dedicated earliest-anomaly probe). Only that selected date may generate at most 16 anomalous pixel samples, extracted deterministically by `Reducer.toList()` in native-grid scan order (no random sampling, no seed); every other date emits aggregate metrics only. Global MODIS grid indices are integer pixel indices (the pixel-centre coordinate floored) and, with raw sample values, exist only in child-process memory and must be removed before result admission or output.

Earth Engine's actual `image.id()` and `system:index` are the date-only identifier `YYYY_MM_DD`; they are not NASA producer-granule IDs. Require that date-only identity plus the exact full projection-inventory image ID, known collection/stream, and UTC date to agree. Derive the MODIS sinusoidal tile from every transient global pixel index produced under the pinned canonical projection: all samples must resolve to the single Lake Balaton tile `(h,v)=(19,4)`, and the HDF local column is `global_x - 19*1200` with the exact `0..1199` bound (the local row analogously uses `global_y - 4*1200`). Only after those gates pass may the runner construct the independent Collection 6.1 `h19v04` NASA producer prefix. Resolve the matching granule through CMR without conflating either identity domain. Require at least one UMM-G granule with `hits` equal to the number of returned items (at most 20); when NASA lists more than one — an original plus reprocessed versions of the same tile and date — deterministically retain the granule with the latest 13-digit production timestamp and record how many were considered and which timestamp was selected. Identical production timestamps fail closed. The `GranuleUR` is the producer granule id with no `.hdf` suffix; the archived file name appends `.hdf`. Require exactly one allowlisted HTTPS HDF data URL whose final path segment is that file name. UMM-G carries no per-file checksum for this product, so fetch the archived `.hdf` file's declared MD5 or SHA-256 checksum and its exact byte size from CMR's legacy `echo10` metadata for the same concept id in one additional bounded request. The CMR `umm_json` search and the CMR `echo10` fetch disable redirects, require zero redirects and exact final scheme/host/path/query identity, and record one transaction each. The HDF download follows up to two hops: LP DAAC 302s a bearer-authenticated protected-granule GET to a short-lived signed download URL (observed: the LP DAAC egress CloudFront distribution; for some DAACs a pre-signed AWS S3 URL). The runner accepts `redirect_count` 0 (served directly) or 1–2 — and for a hop, only when the target is `https` on an allowed NASA-egress host (`*.cloudfront.net`, an AWS S3 host, or `data.lpdaac.earthdatacloud.nasa.gov`) whose path still carries the granule `.hdf` file name as a full segment; it then re-requests without the `Authorization` header. The bearer token is only ever sent to `data.lpdaac.earthdatacloud.nasa.gov`; a redirect elsewhere fails closed. Three supervised transactions per verified granule (cmr, echo10, hdf). Download once using an operator-supplied Earthdata bearer token into a uniquely named temporary file, enforce both the declared checksum and the declared byte size, require the exact five named 1200×1200 HDF4 SDSs (`QC_Night`, `LST_Night_1km`, `Night_view_time`, `Night_view_angl` — the HDF-EOS2 name is truncated with no trailing "e" — and `Clear_night_cov`), and compare their raw values and provider-range mask states with every transient Earth Engine sample. Every SDS handle, HDF dataset, and file is closed/deleted in `finally`; verified evidence requires no temporary residue or persisted raw HDF. The pinned runtime requires `pyhdf==0.11.7` and `EARTHDATA_BEARER_TOKEN`. Missing support stops before Earth Engine initialization. This is a feasibility gate, not permission to substitute another service or source.

## Requests and limits

Execution is sequential:

- four Earth Engine canonical metadata requests;
- one Earth Engine runtime fixture;
- eight Earth Engine projection inventories;
- eight Earth Engine earliest-anomaly probes, one per `(window, stream)`;
- 224 Earth Engine comparison batch requests: four windows × two nighttime streams × four treatments × seven fixed 2-date batches, with A/B/C evaluated simultaneously; the 14 per-date records per `(window, stream, treatment)` are reassembled in Python before validation;
- zero to eight NASA source triples — one CMR `umm_json` search, one CMR `echo10` checksum fetch, and one authenticated HDF download (up to two validated hops to a NASA-egress host) — for each selected stream-season anomaly (0 to 24 requests).

Thus exactly 245 Earth Engine requests and between 0 and 24 NASA source requests are possible. Every request has one attempt, no automatic retry, and a hard monotonic `480.000`-second supervisor cutoff. The complete child tree is terminated at cutoff. The independent session ceiling is 165 minutes.

A fixed `COMPARISON_REQUEST_PAUSE_SECONDS = 8.0` drain pause precedes each of the 224 comparison batch requests. The pause is clamped so it never encroaches on the session budget, is not a retry, and adds no Earth Engine request. It is emitted as a coordinate-free `NIGHTTIME_QA_COMPARISON_CONCURRENCY_PAUSE` log line, which is not a lifecycle marker.

## Acceptance and interpretation

Acceptance requires 32 validated comparison results (each reassembled from its seven date batches), 112 unique stream-date observations represented across exactly 448 treatment-date records, complete seasonal and shoreline summaries, and exactly eight original-source verification outcomes (verified or legitimately not applicable). Output and logs must pass recursive coordinate exclusion.

The result describes coverage and temperature selectivity under three candidate rules. It does not establish that a candidate is scientifically optimal, does not authorize relaxing the completed strict engineering rule, and does not resolve `QA-002`.
