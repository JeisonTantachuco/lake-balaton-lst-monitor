## Finding 1 — BLOCKING — empty distribution groups raise a server-side error

**Location:** `run_nighttime_qa_candidate_comparison_ee.py`, `_distribution()` (the `min`, `max`, and `exact_type7()` expressions).

**Description.** For every treatment-date the runner builds value distributions for five groups (`A∩B`, `A_only`, `B_only`, `B`, `C\B`). When a group selects zero pixels — which is common on cloudy nights, and which `AUDIT-011` already demonstrated is the dominant nighttime case (final coverage was 0 % on every date in these windows) — the reduced value list is empty and `size = 0`. The code then evaluates, among others:

```python
"min": ee.Algorithms.If(size.gt(0), ordered.get(0), None)
"max": ee.Algorithms.If(size.gt(0), ordered.get(size.subtract(1)), None)
# and, inside exact_type7():  ordered.get(lower) / ordered.get(upper), with lower == -1 when size == 0
```

`ee.Algorithms.If` in Earth Engine evaluates **both** branches; it is not short-circuit. `ee.List([]).get(0)` and `ee.List([]).get(-1)` raise an "index out of bounds" computation error, so the entire comparison request fails even though the guard condition is false.

**Consequence.** The run fails closed — no incorrect data is produced, and the failure occurs during the first comparison request (roughly request 14 of 45), *before* any CMR or Earthdata download — but the diagnostic **cannot produce an accepted result** until this is corrected. An authenticated session and Earth Engine quota would be spent for no output.

**Why the offline suite did not catch it.** The self-tests exercise only the pure-Python `type7()` helper and the `validate_*` functions against synthetic dictionaries. The Earth Engine `_distribution` graph has never been evaluated (no authenticated run has occurred). The Python validation layer already handles empty groups correctly (`_validate_distribution` expects `None` statistics when `value_count == 0`); only the server-side graph construction is defective.

**Fix direction.** Keep the count fields (`member_pixel_center_count`, `value_pixel_center_count`, `type7_value_list_count`, `value_area_m2`) computed unconditionally, and make the value-list indexing safe: derive a non-empty `safe` list (`safe = ee.List(ee.Algorithms.If(size.gt(0), ordered, ee.List([0])))`), index into `safe` for `min`/`max`/percentiles, and null every value-derived statistic out through the existing `ee.Algorithms.If(size.gt(0), …, None)` wrapper. This preserves the exact Type-7 `h=(n-1)p` linear-interpolation estimator the specification requires for non-empty groups, and yields explicit nulls for empty groups, matching the Python validator's existing contract.

**Verification required after fix.** The first authenticated comparison request against a window containing a fully-masked nighttime date (e.g. `winter_2024`) must complete and return `None` statistics for the empty groups with the count fields at zero.

## Finding 2 — LOW — sampling date and verification date can disagree (original 0 m treatment only)

**Location:** `graph()` (`earliest_anomaly_index` via a region `Reducer.min()`) versus `select_source_verifications()` (re-derives the earliest date from `metric_map(record)["M0_D_gt0"]["pixel_center_count"] > 0`).

**Description.** The in-graph earliest-anomaly-date selection uses an area/region reduction; the Python-side selection uses pixel-centre counts. If the only `M0 & D>0` pixel on the true-earliest date has its centre just outside the analysis geometry, the two selectors can pick different dates. `select_source_verifications()` would then look up transient samples under a key the graph never populated and raise `AdmissionFailure("ANOMALY_WITHOUT_BOUNDED_SOURCE_SAMPLE")`.

**Consequence.** Fails closed; only affects `EROSION_0000M`; may not trigger on the actual data. Worth a targeted consistency check (both selectors keyed on the same pixel-centre predicate) or an explicit note in the report if it occurs.

## Finding 3 — LOW — CMR "exactly one granule" assumption

**Location:** `parse_cmr_granule()` requires `payload["hits"] == 1` and a single item.

**Description.** `MOD11A1.061` / `MYD11A1.061` normally expose one granule per tile per day, but CMR occasionally retains duplicates from reprocessing campaigns. A duplicate would raise `CMR_EXACTLY_ONE_GRANULE_FAILED`.

**Consequence.** Fails closed with no substitution; would require a re-run or a bounded specification amendment (e.g. deterministic selection of the most recent production date) if encountered.

- **Candidate logic:** `candidate_membership()` and the exhaustive 0–255 QC-byte self-test correctly implement A = `V & M=0`, B = `V & M∈{0,1} & D=0 & E=0 & T=0`, C = `V & M∈{0,1} & D=0 & E≤1 & T≤1`; A-non-nested-with-B and B⊆C are asserted; tier partitions (`B_M0 + B_M1 = B`, `B + C\B_M0 + C\B_M1 = C`) and histogram↔metric identities are enforced in `validate_record`.
- **Type-7 (Python helper):** `type7()` reproduces the `h=(n-1)p` estimator (`type7([1,2,3,4], 0.25) == 1.75`, `… 0.50 == 2.5`).

- **Coordinate-free discipline:** transient global pixel indices and raw values live only in child-process memory and are dropped by `validate_record` before admission; `validate_coordinate_free` is applied recursively to every record, result, source-evidence item, and the terminal payload; the four forbidden-key fixtures reject.
